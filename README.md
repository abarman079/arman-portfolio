I work mainly across **full-stack development, backend systems, applied machine learning, computer vision, and data-oriented applications**.

## `05 / ENGINEERING APPROACH`

```text
UI
 ↓
application behavior
 ↓
API + authorization
 ↓
data model
 ↓
testing
 ↓
deployment
 ↓
observe what actually breaks
 ↓
improve
```

A few principles show up repeatedly in my work:

- **Authorization belongs behind the interface.** UI restrictions are not security boundaries.
- **Architecture should match the problem.** I prefer clear system boundaries over unnecessary abstraction.
- **Metrics need context.** Research results should include the dataset, split, evaluation conditions, and limitations.
- **Motion is an enhancement.** Important content should survive mobile constraints and reduced-motion preferences.
- **A finished feature includes failure states.** Validation, empty states, authorization, and recovery paths matter too.
